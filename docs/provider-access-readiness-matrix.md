# Provider Access Readiness Matrix

This matrix is the no-secret control record for provider readiness across Mission Control and ClinicGrower. It records ownership, environment coverage, approval state and evidence requirements only. Do not paste API keys, passwords, recovery codes, session cookies, OAuth tokens or unredacted provider exports into this file, ClickUp, screenshots or QA artifacts.

## Readiness States

- `Ready`: owner, access route, test account or sandbox, credential location, renewal note and monitoring/fallback are all evidenced.
- `Partial`: engineering integration exists, but one or more provider-side evidence items are missing.
- `Blocked`: provider owner, business approval, paid plan, console access or account decision is missing.
- `Not required`: the provider is intentionally out of scope for the current release.

## Brevo Red Gate Checklist

The Brevo incident remains blocked until provider-owner evidence is collected. The required no-secret evidence is:

- named operator/device and business approval for the 17 Aug 2026 login/API-key sequence
- Brevo user inventory, active sessions and recovery details
- API-key scope and storage location, without the key value
- 2SV/MFA evidence
- confirmation that the former-user account/contact/test route has been removed or explicitly approved
- controlled delivery retest to an approved mailbox
- residual risk statement

If any operator/session/key is unauthorised, revoke and rotate through the approved secret-rotation process. Do not record secret values in ClickUp or this repository.

## Review Cadence

- Engineering can maintain the integration and no-secret matrix.
- Provider/account owners must attach or reference provider-console evidence in the approved external system.
- Production readiness requires every active provider to be `Ready` or to have an approved fallback.
- This document should be reviewed after any provider account change, new integration, credential rotation, or incident.
